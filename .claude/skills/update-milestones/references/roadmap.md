# Hosspie 로드맵

> 이 문서는 CEO 스킬 실행 시 자동으로 참조되며, 마일스톤 리뷰 시 갱신됩니다.
> **범위**: 마일스톤 이름, 전략적 목표, 핵심 와우 포인트, 성공 지표까지. 각 마일스톤 내부의 Phase·기능 분해·구현 순서는 CEO 영역이 아닙니다 — 별도 실행 계획에서 관리합니다.

## 전략 원칙

**피드백 주도 확장.** M1은 최소 MVP로 시작해 실제 사장님 사용 피드백을 수집한 뒤, M2 이후 우선순위와 스펙을 재확정한다. "가설로 다 설계하지 않는다."

## 현재 마일스톤

### M1: MVP — 스태프 관리 (최소 제품) 🔜

**전략적 목표**: 게스트 관련 기능을 모두 제거한 최소 MVP. 게스트하우스 사장님 5곳에 무료 베타 배포 → 실제 사용 피드백 수집 → M2 이후 방향을 피드백 기반으로 재확정.

**핵심 가치**: "엑셀+카톡으로 하던 스태프 관리를 앱 하나로."

**와우 포인트**:
1. **스마트 스케줄링** — 스태프가 가능/불가능 날짜 등록 → 자동 균등 분배 → 교체 요청·수락 플로우
2. **운영 매뉴얼** — 사장님이 작성 → 신규 스태프 온보딩 시 자동 노출 → "사장님께 물어보기 전에 먼저 보는 지침"
3. **오늘의 주의사항** — 사장님이 홈에 게시 → 스태프 출근 시 확인

**포함 범위 (상위 수준)**:
- 인증 & 온보딩 (사장님/스태프 소셜 로그인, 게스트하우스 기본 정보)
- 스태프 초대 (핸드폰 번호 SMS)
- 스태프 근무 일정 관리 (가능/불가능일, 자동 스케줄, 교체 플로우)
- 운영 매뉴얼 (사장님 작성 → 신규 스태프 자동 온보딩)
- 오늘의 주의사항 (홈 게시)

**명시적 비포함**:
- ❌ 객실 정보 (M3로)
- ❌ 게스트하우스 소개/이벤트 설정 (M3로)
- ❌ 간편 게스트 등록 & 안내 문자 (M3로)
- ❌ QR 체크인 & 미니 게스트 웹 (M3로)
- ❌ 일일 인수인계 노트 (폐기)
- ❌ 유료 전환 모델 (M2 이후로 보류)

**성공 지표**:
- 게스트하우스 5곳 베타 도입
- 주 3회 이상 앱 접속률
- 스케줄 자동 생성 실사용률
- 운영 매뉴얼 작성 게스트하우스 비율
- **정성 지표 (가장 중요)**: 사장님 인터뷰 → 게스트 응대·등록·관리 영역의 실제 페인 파악

## 향후 마일스톤 *(전부 잠정 — M1 피드백 후 확정)*

### M2: 스태프 구인구직 *(잠정)*

**전략적 목표**: 구인→면접→채용→운영 매뉴얼→스케줄까지 끊김 없는 연결. M1의 스태프 관리와 자연스럽게 이어지는 사장님 중심 올인원.

**핵심 가치**: "채용 확정 순간 스태프로 자동 흡수." 네이버 카페의 단절된 구인·관리를 하나로.

**아키텍처 방향**: 게스트 웹 서비스의 구인구직 탭. 마이크로 프론트엔드로 분리. Admin App에서는 WebView로 구인 화면 import.

**수익**: 구독 포함 + 구인 공고 부스팅(건당).

**핵심 성공 지표**:
- 구인 공고 게시 건수
- 채용 → 스태프 자동 등록 전환율
- 구독 유지율 (월간)

### M3: 게스트 관리 & 게스트 웹 *(잠정)*

**전략적 목표**: M1에서 빠진 게스트 관련 기능 일체를 사장님 피드백 기반으로 재설계. 게스트 경험을 본격화하여 게스트하우스의 커뮤니티 가치를 높임.

**핵심 가치**: 사장님 수작업(게스트 정보 입력, 안내 문자, 채팅방 생성)을 자동화하고, 게스트끼리의 연결을 플랫폼이 매개.

**후보 기능 (피드백 후 확정)**:
- 게스트하우스 정보 확장 (객실, 이벤트 설정)
- 간편 게스트 등록 (LLM 파싱으로 예약 내역 사진/텍스트 자동 추출)
- 개인화된 안내 문자 자동 발송
- QR 체크인 & 미니 게스트 웹
- 게스트 채팅 (오늘의 채팅방 자동 생성)
- 장소 공유 & AI 코스 추천 (구독 한정)

**핵심 성공 지표**:
- 게스트 등록 수
- 게스트 채팅 활성률 (일일 메시지 수)
- 채팅 아카이브 인사이트 축적량

### M4: 예약 시스템 *(잠정)*

**전략적 목표**: 네이버 예약·야놀자·여기어때·Airbnb·Booking·인스타 DM으로 파편화된 예약을 하나의 인박스로 통합. 가장 큰 잠재 수익원.

**핵심 가치**: "엑셀+카톡으로 예약 채널 관리"에서 "모든 채널 한 화면"으로. 이중 예약 구조적 방지.

**전략 방향 (리서치 기반)**: 직접 API 연동은 대부분 불가(야놀자·여기어때·네이버 공개 API 없음, Airbnb·Booking은 파트너 심사 필요). 현실적 접근:
1. **LLM 파싱** (수동 스크린샷/텍스트 붙여넣기) — day 1부터 모든 채널 커버
2. **iCal 동기화** (Airbnb, Booking.com) — 자동 이중 예약 방지
3. **ONDA 파트너십** (장기) — 국내 채널매니저 60% 점유, 5대 채널 커버

**핵심 성공 지표**:
- 예약 건수 통합 관리율
- 이중 예약 발생 감소율
- 구독 전환율
