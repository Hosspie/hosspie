# M2~M4 순서 변경 및 수익 모델 재설계

- 날짜: 2026-04-04
- 트리거: feedback
- 모드: 확장 (마일스톤 순서 변경 + 수익 모델 전면 재설계)

## 배경

이전 리뷰에서 M1 브릿지 요소를 추가한 후, M2~M4의 방향성과 순서를 점검. 수익 모델의 약점을 발견하고 전면 재설계.

## 핵심 판단

### 1. 마일스톤 순서 변경: 구인구직(M4→M2)을 게스트 웹(M2→M3)보다 앞으로

**변경 전**: M1(스태프 관리) → M2(게스트 웹) → M3(예약) → M4(구인구직)
**변경 후**: M1(스태프 관리) → M2(구인구직) → M3(게스트 웹) → M4(예약)

**이유:**
- M1→M2 흐름이 **사장님 중심 올인원**(스케줄→인수인계→구인)으로 단단해짐
- 스태프 교체 주기가 빠른 게스트하우스 특성상, 구인구직이 스태프 관리 바로 다음에 오는 게 자연스러움
- 게스트 웹(채팅, AI 코스)은 장소 데이터 축적이 필요하므로 시간을 벌 수 있음

### 2. 수익 모델 전면 재설계

**변경 전**: M1 무료 → M2+ 구독 전환
**변경 후**: M1부터 유료 (3개월 무료 체험 후 자동 전환)

| 티어 | 대상 | 가격 | 포함 기능 |
|------|------|------|----------|
| 스몰 | 소규모 게스트하우스 (스태프 ~3명) | 저가 | M1 전체 기능 |
| 비즈니스 | 대규모 게스트하우스 (스태프 4명+) | 고가 | M1 전체 + 추가 기능 |

추가 수익원:
- M2: 구인 공고 부스팅 (건당 과금)
- M3: 채팅/AI 코스는 구독에 포함 (가격 유지, 가치 강화 → 이탈 방지)
- M4: 예약 수수료 (건당 3~5%)

**핵심 결정:**
- 무제한 게스트 등록을 프리미엄 기능으로 쓰지 않음 (소규모 게스트하우스에겐 메리트 없음)
- 처음부터 유료 제품으로 포지셔닝, 3개월 무료 체험으로 진입 장벽 낮춤
- 규모별 차등 가격으로 소규모/대규모 모두 커버
