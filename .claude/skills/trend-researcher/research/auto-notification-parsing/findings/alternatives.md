# 대안 접근법

이메일 인바운드, SMS 외의 자동 수신 경로들. 주로 **네이버 앱 푸시/야놀자 앱 푸시** 같은 "앱 전용 알림"을 커버하기 위한 대안.

---

## 1. Android NotificationListenerService

### 개요
- Android 시스템 레벨 API. 사용자가 "알림 접근 권한"을 수동으로 활성화하면, 다른 앱이 띄운 **모든 알림의 텍스트·아이콘·패키지명**을 실시간으로 읽을 수 있음.
- 네이버 앱이 "새 예약이 들어왔습니다 - 홍길동님 2박" 알림을 띄우면, Hosspie가 이 텍스트를 가로채서 백엔드로 전송 → LLM 파싱 가능.

### React Native / Expo 라이브러리
- **`expo-android-notification-listener-service`** (SeokyoungYou): Expo Module. 허용 패키지 설정, `onNotificationReceived` 이벤트 제공. Dev Client/Prebuild에서 동작.
- **`react-native-android-notification-listener`** (leandrosimoes): 오래된 RN bare 프로젝트용. 유지보수 다소 뜸함.
- Expo Managed는 직접 불가, Config Plugin + Prebuild 필요.

### 장점
- **iOS 불가를 감안하더라도, 한국 시장은 Android 비중이 높음** (70% 이상). 사장님 페르소나 특성상 Android 비중이 더 높을 수 있음.
- 네이버 앱 푸시, 야놀자 사장님 앱 푸시, 여기어때 파트너 앱 푸시를 한 번에 커버 가능.
- 이메일처럼 포워딩 설정이 필요 없음 → 사용자 UX 단순 (권한 활성화 1회).

### 단점 / 리스크
1. **Google Play 정책 리스크 (가장 큼)**:
   - Google은 `BIND_NOTIFICATION_LISTENER_SERVICE` 사용에 "앱의 핵심 기능에 반드시 필요하고 대체 수단이 없다"는 정당성을 요구.
   - 2024 정책 업데이트에서 민감 권한 심사 강화 추세.
   - 심사 거절 또는 업데이트 지연 가능성 존재. 단, **"예약 알림 통합 관리"는 정당한 use case로 인정받을 수 있는 여지**가 있음 (동일 카테고리의 접근성 앱, SmartThings 등이 통과된 전례 참고).
2. **iOS 미지원**: iOS는 NotificationListener에 해당하는 API가 없음. 크로스 플랫폼 일관성 훼손.
3. **배터리/백그라운드 제약**: Android 14+에서 백그라운드 서비스 제약이 심해짐. Foreground Service + persistent notification 조합 필요할 수 있음 → UX에 persistent notification이 항상 떠 있게 됨.
4. **알림 텍스트 품질**: 푸시 알림은 요약 텍스트 ("홍길동님 예약") 정도만 포함. 금액·방 타입 등 상세는 없을 수 있음 → 앱 딥링크 타고 들어가거나 추가 조회 필요.

### 권장 사용 시나리오
- **"고급/선택 기능"으로 제공**: 기본은 이메일 인바운드 경로, 추가로 "Android 사용자는 알림 접근 권한 켜면 네이버/야놀자 자동 수신" 옵션.
- 사용자에게 명확히 고지하고 동의 받음.
- Play Store 심사 시 정당성 서술 + 데모 비디오 준비.

## 2. 카카오톡 알림톡 API (역방향 가능성)

### 결론: **불가능**
- 카카오 알림톡 API는 **기업이 고객에게 발송**하는 서비스. SOLAPI, 알리고, NHN Cloud 등 공식 파트너(딜러)를 통해 제공.
- 기업(Hosspie)이 **알림톡을 수신**할 수 있는 API는 존재하지 않음.
- 즉, "각 OTA가 사장님에게 카카오 알림톡을 보내고, 그걸 Hosspie가 받는다" 시나리오는 구조적으로 불가능.

### 응용 가능성: Hosspie → 사장님 발송 용도
- Hosspie가 사장님에게 체크인 리마인더, 오늘의 예약 요약 등을 알림톡으로 발송하는 용도로는 사용 가능.
- 파싱/수신과는 무관한 기능.

## 3. 가상번호 (050) SMS 수신

### 국내 서비스 현황
- **050 비즈콜**: 오픈 API 제공 (번호 설정, 콜로그·SMS 수신 웹훅).
- **KT Enterprise 0502 안심번호**: CDR 데이터, SMS 수신 API.
- **인포필러**: MMS 수신 가능한 안심번호, 실시간 CDR 통계 API.
- **NURIGO/CoolSMS**: 050 번호 발급 + API.

### 시나리오
1. Hosspie가 사장님별 050 번호 발급.
2. 사장님이 네이버 스마트플레이스, 야놀자, 여기어때 파트너 대시보드에서 **연락처를 050 번호로 교체**.
3. OTA가 해당 050 번호로 SMS 발송 → 통신사 게이트웨이 → Hosspie 백엔드 웹훅 수신.
4. LLM 파싱.

### 장점
- 앱 권한 문제 완전 우회.
- iOS/Android 무관.
- 사장님 본인 폰에 SMS가 전달되지 않거나 동시 전달(통신사 설정에 따라) → 푸시는 Hosspie 앱에서 받음.

### 단점
1. **운영 비용**: 번호당 월 2,000~10,000원 + SMS 수신 건당 과금 가능. 사용자 1,000명 × 월 5,000원 = 월 500만원 → 수익 모델 없이 초기 감당 불가.
2. **네이버는 이미 SMS 중단** → 커버리지 제한.
3. **사장님의 번호 교체 저항**: 기존 연락처로 게스트 문의/예약 확인을 받아왔기 때문에 번호 교체는 업무 변경 요구.
4. **법적/약관 이슈**: OTA 이용약관에 "허위 연락처 등록 금지" 조항이 있을 수 있음. 050은 허위가 아니지만 "예약 정보 제3자 자동 전달" 관점에서 회색지대.
5. **통신사 위탁 계약**: 050 사업자와 법인 계약 필요. 1인 사업자는 개설 가능하지만 초기 서류/심사.

### 판단
- **Phase 3+ 옵션**. 유료 플랜 가입자에게 "프리미엄 자동 수신" 기능으로 원가 전가 가능해지는 시점에 도입.
- MVP에서는 제외.

## 4. OCR + 수동 스크린샷 경로

### 시나리오
- 자동 수신이 어려운 케이스(네이버 앱 푸시를 iOS 사장님이 받는 경우 등)를 위한 폴백.
- 사장님이 네이버 앱에서 알림 화면 스크린샷 → Hosspie 앱의 "예약 추가" 버튼에서 이미지 업로드 → 백엔드 OCR(Google Cloud Vision, Naver Clova OCR) → LLM 파싱.

### 장점
- 모든 채널 대응 가능 (폴백).
- 사장님의 심리적 진입 장벽 낮음 (스크린샷은 이미 익숙한 행동).
- 법적으로 안전 (사장님이 명시적으로 업로드).

### 단점
- 자동이 아님. 사장님이 매번 수동 액션 필요.
- OCR 비용: Clova OCR ~ 건당 10원 / Google Vision 1000건/월 무료.

### 활용
- **MVP 필수 기능으로 포함**. 자동 수신이 실패하거나 미지원 채널일 때의 안전망.
- iOS Share Extension으로 "공유 → Hosspie로 예약 추가" UX 제공하면 2~3탭만에 완료 가능.

## 5. 알림톡 파싱 (발송처가 OTA인 경우)

- 네이버/야놀자/여기어때가 사장님에게 알림톡으로 예약 알림을 보내는 경우가 있는지 확인 필요. 현재 리서치로는 명확하지 않음.
- 설령 보낸다 해도 **수신 측에서 알림톡 내용을 읽는 방법은 SMS와 동일한 제약**: iOS 불가, Android NotificationListenerService로 카카오톡 앱 알림을 가로채는 방식 (위 §1과 동일한 리스크).
