# 자동 알림 수신/파싱 기술 실현 가능성 리서치

**리서치 일자**: 2026-04-04
**대상 기능**: Hosspie M2 "멀티 채널 예약 통합 관리"
**기술 스택 전제**: Expo/React Native, NestJS GraphQL, Supabase PostgreSQL, 1인 개발자

---

## TL;DR (핵심 결론)

1. **완전 자동화는 모든 채널에서 불가능**. 채널별로 알림 경로가 다르고(네이버=앱 푸시 중심, OTA=이메일+앱 푸시), OS/플랫폼 정책이 가로막는다.
2. **가장 현실적인 경로는 "이메일 인바운드 파싱"**. 사장님이 Gmail 필터로 Hosspie 전용 주소에 자동 전달 설정 → Cloudmailin/Postmark가 웹훅으로 파싱. Airbnb·Booking.com·여기어때 파트너·일부 네이버 케이스를 커버한다.
3. **SMS 자동 수신은 현실적으로 포기해야 함**. iOS는 원천 불가, Android는 Google Play 정책상 "기본 SMS 앱"이 아니면 `READ_SMS` 권한 거의 불가 (2019년부터 엄격).
4. **네이버는 2023년부터 SMS 알림 → 네이버 앱 푸시로 이전**. 네이버 앱 푸시는 외부 앱이 가로챌 방법이 없다 (Android `NotificationListenerService`는 가능하지만 Play Store 정책 리스크 큼).
5. **카카오 알림톡은 발송만 가능, 수신은 API 미지원**. 대안 아님.
6. **1인 개발자 추천**: Phase 1 = 이메일 인바운드 + LLM 파싱(OTA 중심), Phase 2 = 네이버는 수동 스크린샷 OCR/붙여넣기 UX + Android 푸시 리스너 옵션 실험, Phase 3 = ONDA 파트너십(별도 리서치 참고).

## 요약 테이블: 채널별 자동 수신 실현 가능성

| 채널 | 주 알림 경로 | 자동 수신 가능성 | 권장 접근 |
|------|-------------|-----------------|----------|
| Airbnb | 이메일 + 앱 푸시 | **높음** (이메일) | 이메일 포워딩 → 인바운드 파싱 |
| Booking.com | 이메일 + 앱 푸시 (Fallback 이메일은 30분 후) | **높음** (이메일) | 이메일 포워딩 → 인바운드 파싱 |
| 여기어때 파트너 | 이메일 + 앱 푸시 + 문자 | **중간** (이메일) | 이메일 포워딩 → 인바운드 파싱 |
| 야놀자 사장님 | 앱 푸시 중심, 이메일 보조 | **낮음** | Android 푸시 리스너(리스크) or 수동 |

## 핵심 발견 요약

### 발견 1: 이메일 인바운드 파싱은 검증된 패턴이다
- Mailparser, Parsio 등 서드파티가 **Airbnb 예약 이메일 파싱을 상용 제품화**해서 판매 중. 포맷이 안정적이라는 뜻.
- Cloudmailin은 월 10,000건까지 **무료**. Postmark Inbound는 월 100건 무료, 이후 $15/월 10k건. 1인 개발 초기 비용이 거의 0원.
- Booking.com은 "Fallback email"이라는 공식 메커니즘이 있음. API 연동 실패 시 30분 후 이메일로 예약 정보 전송 → 사실상 "이메일로 받기"가 정식 채널.

### 발견 2: SMS는 OS 정책 벽을 넘을 수 없다
- **iOS**: 앱은 SMS 내용을 읽을 수 없다 (보안 정책). `IdentityLookup` 프레임워크는 "알 수 없는 발신자의 스팸 분류"용일 뿐, 내용을 앱이 수신하지 못함.
- **Android**: 2019년 Google Play 정책 변경으로 `READ_SMS`/`RECEIVE_SMS`는 "기본 SMS 앱" 지정된 앱만 허용. Hosspie는 해당 안 됨 → 심사 거부 확정.
- Expo `react-native-expo-read-sms`, `react-native-get-sms-android` 등은 기술적으로 동작하지만 **Play Store 심사 통과 불가**. 사이드로드/엔터프라이즈 배포용으로만 의미.

### 발견 3: 네이버 메일은 외부 자동 포워딩을 지원하지 않는다
- 네이버 메일은 정책상 외부 주소로의 자동 포워딩 기능 미제공. POP3로 당겨오는 건 가능하지만 UX 복잡.
- **해결책**: 사장님에게 Gmail/Outlook 등 외부 메일을 "예약 전용 메일"로 쓰도록 가이드 → 채널 파트너 사이트에서 해당 메일로 알림 받기 설정.
- 다음(Daum) 메일은 외부 포워딩 지원 (조건 확인 필요).

### 발견 4: 네이버 예약 알림 = 네이버 앱 푸시 (가장 어려운 케이스)
- 2023년 9월부터 네이버 예약 SMS 알림이 중단되고 **네이버 앱 내 알림**으로 전환됨.
- 이메일 알림은 여전히 설정 가능하지만 기본이 아님 → 사장님이 직접 설정해야 함.
- 네이버 앱 푸시를 외부 앱이 가로채려면 Android `NotificationListenerService`만 가능. iOS는 불가.

### 발견 5: Android NotificationListenerService는 "가능하지만 위험"
- 라이브러리 존재: `expo-android-notification-listener-service`, `react-native-android-notification-listener`.
- 기술적 가능: 네이버·야놀자·여기어때 앱이 띄우는 알림의 텍스트를 읽을 수 있음.
- **Play Store 리스크**: Google은 `NotificationListenerService` 사용에 "핵심 기능에 반드시 필요하고 대체 불가" 정당성을 요구. 2024 정책 업데이트에서 점점 더 엄격해지는 추세. 심사 거절/앱 리뷰 지연 가능성 큼.
- 1인 개발자가 초기 MVP에서 쓰기엔 리스크 크지만, **옵셔널 기능("고급 자동 수신 모드")으로 명확히 분리 + 사용자 동의** 구조면 통과 사례 존재.

### 발견 6: 카카오 알림톡은 발송만 가능
- 알림톡 API는 **기업 → 사용자 발송 전용**. 기업이 알림톡을 수신하는 API는 제공하지 않음.
- "각 OTA가 사장님에게 알림톡을 보낸다 → Hosspie가 받는다" 시나리오는 불가능.

### 발견 7: 가상번호(050) SMS 수신 API는 존재
- 050 비즈콜, KT Enterprise 0502, 인포필러 등이 **CDR/SMS 수신 오픈 API** 제공.
- 이론적 시나리오: 사장님이 OTA에 등록한 연락처를 Hosspie가 발급한 050 번호로 바꾸면 SMS를 백엔드에서 수신 가능.
- **문제점**: (1) 월 운영비(번호당 수천원~수만원) × 사용자 수 = 1인 개발자 초기엔 부담. (2) 네이버는 이미 SMS 중단 → 커버 범위 제한. (3) 사장님 기존 업무 번호 교체 저항감 큼. (4) 개인정보보호법상 수신 동의/위탁 절차 복잡.
- 결론: Phase 3+ 옵션. 초기엔 제외.

## 프라이버시/법적 주의사항

- **개인정보보호법**: 이메일·SMS·알림에는 예약자의 개인정보(이름·연락처·여권번호 등)가 포함됨. Hosspie가 이를 수신·저장하면 **개인정보 처리자**가 되고, 사장님과 위탁 계약 + 이용자 동의가 필요.
- **GDPR**: 해외 예약(Airbnb/Booking) 데이터 포함 시 EU 거주자 정보 처리에 GDPR 적용 가능.
- **약관 위반 리스크**: OTA 각사의 이용약관이 "예약 정보 제3자 자동 전송"을 금지할 수 있음. 특히 Airbnb/Booking은 공식 Connectivity Partner 심사를 통과해야 정당한 연동 경로로 인정.
- **실무 권고**: 사장님이 "자기 이메일을 자기 업무 도구(Hosspie)로 전달"하는 구조는 비교적 안전. 사장님 본인의 데이터이고 본인의 동의 하에 이뤄지기 때문. 단, 이용약관에 명시 필수.

## 최종 추천 (간략)

- **Phase 1 (MVP, 0~3개월)**: 이메일 인바운드 파싱(Cloudmailin 무료 티어) + LLM 파싱 + 수동 붙여넣기 폴백 UX. iOS/Android 공통.
- **Phase 2 (3~6개월)**: Android 전용 "고급 모드"로 NotificationListenerService 옵션 추가. 네이버 앱 푸시/야놀자 앱 푸시 커버.
- **Phase 3 (6개월+)**: ONDA 채널매니저 파트너십(멀티채널 API 리서치 참고). 정식 API 연동.
