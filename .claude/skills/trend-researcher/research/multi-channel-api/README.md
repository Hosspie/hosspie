# 멀티 채널 예약 API/연동 가능성 조사

> 조사 일자: 2026-04-05
> 목적: Hosspie 앱에서 여러 예약 채널(네이버 예약, 야놀자, 여기어때, Airbnb, Booking.com, 카카오톡/인스타그램 DM)의 예약 데이터를 통합 관리하기 위한 기술적 연동 방안 파악

## 조사 범위

1. 5개 핵심 예약 채널의 공개 API·웹훅·iCal 지원 여부
2. 한국 숙박업용 채널 매니저(Channel Manager) 생태계 (ONDA, eZee, 야놀자클라우드 등)
3. 비구조적 채널(카카오톡, 인스타그램 DM)의 예약 수집 자동화 가능성
4. 소규모 게스트하우스가 현실적으로 접근 가능한 연동 경로

## 핵심 발견 (TL;DR)

### 1. "직접 API 연동"은 소규모 업체에 사실상 닫혀 있다

- **Airbnb·Booking.com**: 공식 API는 존재하지만 **"Connectivity Partner" 심사 통과 기업(PMS·채널매니저)만 접근 가능**. Booking.com은 2025~2026년 신규 파트너 등록을 일시 중단한 상태. Airbnb도 "Preferred Software Partner" 자격이 필요.
- **야놀자·여기어때**: 공식 개발자 포털·공개 API 문서 **없음**. 파트너센터(업주용) 앱과 내부 B2B API만 존재. 외부 개발자가 직접 연동할 창구는 확인되지 않음.
- **네이버 예약**: **숙박 업종은 네이버 예약 API 연동 대상에서 제외**되어 있음 (행사·스포츠·공연과 함께). 스마트플레이스 기반이나 직접 파트너십을 통해서만 접근 가능.

### 2. iCal(.ics) 캘린더 동기화는 "Airbnb ↔ Booking.com"만 실질적 선택지

- Airbnb: iCal export/import 지원. 3시간 주기 업데이트. **오버부킹 위험 존재**.
- Booking.com: iCal export 지원하지만 **XML/채널매니저 연동 중이면 비활성화**, 객실 타입·유닛 수에 제한.
- 야놀자·여기어때·네이버 예약: **iCal 지원에 대한 공식 문서 확인되지 않음**. 사실상 지원하지 않는 것으로 판단.

### 3. 현실적으로 가장 빠른 경로: 채널 매니저(특히 ONDA)를 중간 다리로

- **ONDA**가 국내 소규모 숙박(펜션·게스트하우스·호스텔) 대상 사실상의 표준. 야놀자·여기어때·네이버·Airbnb·Booking.com·Agoda·Expedia 등 40+ 채널을 단일 연동으로 커버.
- ONDA는 "파트너 PMS" 프로그램을 운영(`pension.onda.me`) — Hosspie 같은 외부 PMS가 ONDA API를 통해 채널 데이터에 접근할 수 있는 가능성이 존재. 공식 파트너 신청(`onda.me/affiliate`) 필요.
- 야놀자클라우드도 자체 CMS를 보유하나 자사 생태계(산하정보기술, 놀유니버스) 내부 연동에 초점.

### 4. 비구조적 채널(카카오·인스타)은 "자동화"보다 "워크플로우 도움"이 현실적

- **카카오톡 알림톡/비즈메시지 API**: 정보성 메시지 **발송**은 가능하나 **수신 예약을 자동 파싱하는 공식 API는 없음**. 챗봇(카카오 i 오픈빌더) + Event API로 예약 봇을 만드는 건 가능.
- **Instagram Graph API**: 비즈니스 계정 DM 수신/발신 API 존재. 단 **24시간 메시지 규칙** 적용, 메타 앱 심사 필요. 키워드 기반 예약 수집 봇(매니챗·소셜비즈 등)이 이미 상용화.
- 현실적 대안: **OCR/수기 입력 + LLM 파싱**으로 예약 정보를 Hosspie로 가져오는 반자동 플로우.

### 5. Hosspie 전략 제안 (요약)

| 단계 | 기간 | 전략 |
|------|------|------|
| **Phase 1 (MVP)** | 0~3개월 | iCal 동기화(Airbnb/Booking.com) + 수기/이메일 파싱(야놀자·여기어때·네이버) + LLM 기반 DM 파싱 어시스턴트 |
| **Phase 2** | 3~9개월 | ONDA 파트너 PMS 프로그램 가입 협상 → 단일 API로 5개 OTA 커버 |
| **Phase 3** | 9~18개월 | Airbnb Preferred Partner 자격 신청, 자체 Connectivity 인증 추진 |

## 중요한 제약과 리스크

1. **야놀자·여기어때 API 비공개**: 이 두 채널이 한국 내수 점유율 1·2위인데 공식 연동 경로가 막혀 있다는 점이 가장 큰 구조적 리스크.
2. **Booking.com 신규 파트너 등록 중단**: 재개 시점 불확실. 재개 전까지 기존 파트너(예: ONDA)를 경유해야 함.
3. **iCal의 3시간 지연**: 오버부킹 방지에 완벽하지 않음. 사용자 대면 UI에서 "대략적 캘린더 통합"이라는 기대치 설정 필요.
4. **네이버 예약 숙박 제외**: 한국 소규모 숙박의 핵심 채널이지만 공식 API 경로가 없음. 스마트플레이스 제휴를 별도로 추진해야 함.
