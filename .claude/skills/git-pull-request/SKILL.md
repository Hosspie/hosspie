# PR 스킬

현재 브랜치의 모든 커밋을 분석하여 PR 제목과 설명을 자동 생성합니다.

## 사전 요구사항

- `gh` CLI 설치 및 인증 완료
- 원격 저장소 push 권한

## 실행 절차

### 1. 베이스 브랜치 선택

현재 브랜치와 가장 가까운 **부모 브랜치 후보 3개**를 자동으로 탐색하여 사용자에게 제시합니다.

**AskUserQuestion**을 사용하여 베이스 브랜치를 선택받습니다:

- 커밋 차이가 가장 적은 브랜치를 권장
- "Other" 선택 시 직접 입력 가능

### 2. 변경사항 분석

부모 브랜치 기준으로 **모든 커밋**을 분석합니다 (최신 커밋만이 아님).

#### 2-1. AI 리뷰 분석

다음 항목을 자동 분석하여 PR 본문에 포함:

**이모지 규칙**:

- ✅ 확인 완료 (AI가 검토 완료)
- ⚠️ 확인 필요 (리뷰어가 직접 검토 필요)

**분석 항목**:

1. **영향 분석**: 변경된 파일을 사용하는 다른 모듈/화면 검색
2. **코드 컨벤션 체크**: `.claude/docs/convention/` 문서 기준으로 검증
3. **문서 동기화 체크**: 관련 문서 업데이트 여부 확인

| 변경 유형        | 필요한 문서 업데이트         |
| ---------------- | ---------------------------- |
| 코드 컨벤션 도입 | `.claude/docs/convention/`   |
| API 변경         | `.claude/agents/backend.md`  |
| DB 스키마 변경   | `.claude/agents/database.md` |

### 3. PR 정보 생성

#### 제목 형식 (반드시 한글로 작성)

```
<type>: <간결한 요약 (한글)>
```

#### 본문 형식 (`.github/pull_request_template.md` 준수)

```markdown
# 🎯 주요 개발 내용

## 1. [주요기능1]

- 상세 설명
  - 세부 내용

## 2. [주요기능2]

- 상세 설명
  - 세부 내용

## 3. [기타 개선사항]

- 추가 변경사항

# 📝 리뷰어 체크 포인트

- [ ] 체크 포인트 1
- [ ] 체크 포인트 2

# 📸 스크린 샷

(해당 시 첨부)

# ⚠️ 주의사항

- 주의사항 (없으면 생략)

# 🤖 AI 리뷰

## 영향 분석

- ⚠️ `파일명` 변경 → `사용처1`, `사용처2`에 영향
- ⚠️ `함수/컴포넌트명` 수정 → 관련 화면 동작 확인 필요

## 코드 컨벤션 체크

- ✅ 컨벤션 준수 (위반 항목 없음)

## 문서 동기화 체크

- ⚠️ 관련 문서 업데이트 필요

---

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

### 4. PR 생성 및 코멘트 추가

#### PR 생성

- Draft PR로 생성 (기본값)
- 원격 저장소에 자동으로 push
- gh CLI 사용

#### 코드 설명 코멘트

리뷰어에게 **설명이 필요한 주요 변경사항**에 라인별 코멘트를 추가합니다.

**코멘트 추가 대상**:

- 복잡한 로직 (100줄 이상 함수, 중첩 조건문 3단계 이상)
- 새로운 함수/컴포넌트 (store, hook, 핵심 컴포넌트)
- 타입 변경
- 비즈니스 로직 (계산식, 상태 전이, 데이터 변환)
- 성능 최적화 (useMemo, useCallback)
- 보안/권한 관련
- API 변경

**작성 원칙**:

- "왜(Why)" 설명 중심
- 영향 범위 명시
- 간결하고 명확하게 (1-2문장)
- 한글 작성

**예시**:

```
✅ 좋은 코멘트: "타입을 string에서 enum으로 변경하여 컴파일 타임에 오타 방지. TherapyScreen, HomeScreen에서 자동완성 가능."
❌ 나쁜 코멘트: "TherapyType enum을 추가했습니다."
```

## 옵션

### Ready PR 생성 (Draft 해제)

```
/pr --ready
```

### 특정 베이스 브랜치 지정

```
/pr --base develop
```

### Reviewer 지정

```
/pr --reviewer @username
```

> **참고**: 기본값은 `--draft`입니다. Ready for review 상태로 생성하려면 `--ready` 옵션을 사용하세요.

## 주의사항

- **PR 제목과 본문은 반드시 한글로 작성** (type, 이모지 제외)
- **커밋되지 않은 변경사항이 있으면 먼저 커밋 필요** (PR 스킬은 커밋된 내용만 분석)
- **PR 생성 전 항상 원격에 push를 먼저 실행** (4단계)
- **코드 설명 코멘트는 주요 변경사항에만 추가** (모든 라인에 코멘트를 달지 않음)
- 코멘트 추가는 선택사항으로, 코멘트가 없어도 PR 생성은 정상 완료됨
- 이미 PR이 있는 브랜치면 기존 PR 업데이트 안내
- force push는 사용하지 않음
