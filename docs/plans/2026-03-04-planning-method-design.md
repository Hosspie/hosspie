# Hosspie 기획 명세서 시스템 디자인

## 배경

게스트하우스 관리 앱(Hosspie)의 요구사항을 체계적으로 정리하기 위한 기획 명세서 시스템을 설계한다.
프론트엔드 개발자, 백엔드 개발자, 퍼블리셔가 공통으로 참고하며, 각 직군이 바로 적용할 수 있는 형태를 목표로 한다.

---

## 요구사항 요약

### 사용자 역할
- **host**: 게스트하우스 오너. 게스트하우스를 등록하고 staff를 초대/관리
- **staff**: host가 초대한 직원. 딥링크를 통해 앱 설치 후 가입

### 인증
- 전화번호 OTP + 소셜 로그인 (카카오/네이버/애플)

### 앱 구조 (admin)
- **로그인** → 미등록 시 **온보딩** → 등록 완료 시 **탭 (4개)**
- 탭: 홈 / 체크인 / 스케줄 / 채팅

### 주요 기능
| 영역 | 기능 |
|------|------|
| 온보딩 | 게스트하우스 정보 등록 (이름, 사진, 전화번호, 파티 방식, 방 정보, 마크다운 안내글) |
| 홈 | 오늘의 공유사항 (host+staff 모두 작성/열람), 체크인 현황 요약, 이번주 스탭 근무표 |
| 체크인 | 게스트 목록 조회, 체크인 상태 토글, 메모 등록, 개인 SMS 발송, 파티 참가 여부 |
| 스케줄 | 이번주 스탭 근무 확인, 근무 등록/수정, 스탭 추가 (딥링크 초대) |
| 채팅 | 게스트하우스↔게스트 1:1 채팅 (host/staff 모두 응대 가능) |
| 프로필 | host: 온보딩 내용 수정, staff: 프로필 수정 |
| 게스트 등록 | 1단계 수동 등록, 향후 자체 예약 시스템 자동 연동 |

### 게스트 접근
- SMS 웹 링크로 채팅 접근
- 향후 게스트용 웹(apps/guest) 별도 개발 예정

### 파티
- 게스트하우스마다 운영 방식 다름 (POT_LUCK / HOST_SERVED / CUSTOM)
- 체크인에서 게스트별 파티 참가 여부 트래킹

### 백엔드
- 기획 명세서에서는 API 인터페이스만 정의 (기술 스택은 별도 결정)

## 설계 결정 사항

### 1. 접근법: 스크린 중심 명세서
- 각 스크린을 단위로 명세 작성
- 스크린별로 기능 목록 + 테스트 케이스를 함께 묶음
- UI 명세(퍼블리셔용), API 명세(백엔드용)는 기획 문서에 포함하지 않음 — 각 직군이 자체 결정

### 2. 기능 코드 체계
모든 기능에 고유 코드를 부여하여 직군 간 소통 시 혼선 방지.

```
코드 형식: {도메인}-{스크린}-{번호}

도메인 접두어:
  AUTH  = 인증
  OBD   = 온보딩
  HOME  = 홈
  CHK   = 체크인
  SCH   = 스케줄
  CHAT  = 채팅
  PROF  = 프로필
  GRST  = 게스트 등록

테스트 케이스 코드: {기능코드}-T{번호}
  예: CHK-LIST-002-T03 = 체크인 상태 토글 기능의 3번째 테스트
```

### 4. 스크린 명세서 템플릿

```markdown
# {스크린명} ({도메인코드}-{스크린코드})

## 개요
- **목적**: ...
- **진입 경로**: `{앱 내 파일 경로}`

---

## 기능 목록 & 테스트 케이스

### {코드}: {기능명}
> {기능 설명}

| 우선순위 | P0/P1/P2 |
|---------|----------|

| 테스트 코드 | 시나리오 | Given | When | Then |
|------------|----------|-------|------|------|
| {코드}-T01 | ... | ... | ... | ... |
```

- **접근 권한**은 개요에 표기하지 않음 — 테스트 케이스에서 host/staff별 분기로 표현
- **진입 경로**는 정확한 스크린 파일명 사용

## 구현 범위

### 이번 기획에 포함
- 로그인 (전화번호 OTP + 소셜 3종)
- 온보딩 (4단계)
- 홈 대시보드
- 체크인 관리
- 스케줄 관리
- 채팅
- 프로필 편집
- 게스트 등록
- SMS 발송 (실제 문자)
- Staff 초대 (딥링크)

### 향후 계획 (이번 기획 제외)
- 게스트용 웹 앱 (apps/guest)
- 자체 예약 시스템
- 예약 플랫폼 자동 연동
